# 古玉鉴真 — 需求与功能实现详细记录

## 项目概述

AI 驱动的古玉鉴定与数据标注系统。面向专业古玉鉴定师和高水平收藏家。

---

## 需求与实现对照

### 1. 系统架构设计

**用户需求：**
> 我需要打造一个古玉鉴定系统，取名为"古玉鉴真"

**实现内容：**
- 项目命名：古玉鉴真 (Ancient Jade Authentication)
- 完整系统架构设计：训练管线 + 推理引擎 + 桌面应用 三层架构
- 技术栈选型：PyTorch + ONNX Runtime + Electron + React + TypeScript

---

### 2. 核心鉴定功能

**用户需求：**
> 核心功能的话，具备鉴定和数据标注的功能，鉴定的话提示用户输入单张或多张同一件玉器的不同视角的图片，特别提示用户输入微距图表现玉器的沁色或者纹饰的工痕

**实现内容：**
- 多视角双流模型架构：MACRO 流 (512×512 整帧) + MICRO 流 (224×224 tile 切图)
- 上传页面提示：提示用户上传不同视角图片 + 微距图（沁色/工痕）
- 微距图自动检测 (分辨率 > 8MP)
- 微距图 tile 切片处理 (224×224, stride 112)

---

### 3. 年代分类体系

**用户需求：**
> 鉴定功能包括给出鉴定年代：文化期、商代、春秋、战国、秦汉、三国两晋南北朝、唐、宋、金元、明、清、民国、出口创汇、现代；给出鉴定结果：真老、新仿

**实现内容：**
- 14 年代分类：A=文化期, B=商代, C=春秋, D=战国, E=秦汉, F=三国两晋南北朝, G=唐, H=宋, I=金元, J=明, K=清, L=民国, M=出口创汇, N=现代
- 5 粗粒度分组：远古/古典/中古/近古/近现代
- 分层交叉熵损失：混淆相邻年代的惩罚 < 混淆跨时代的惩罚
- 真伪二分类 (真老/新仿) + Focal Loss 处理类别不平衡

---

### 4. 产品形态

**用户需求：**
> 产品形态的话，暂时运行在桌面，但是未来考虑在手机端（ios以及安卓）甚至微信小程序上运行

**实现内容：**
- Phase 1: Electron + React 桌面应用
- 目录预留 mobile/ 结构（React Native + 微信小程序）
- shared/ 共享类型和常量定义，便于跨平台复用

---

### 5. AI 模型选型

**用户需求：**
> 技术路线的话，考虑基于AI甚至大模型的图像识别，考虑到当前PC的硬件，以及未来在手机上部署，请选择能在端侧部署下的参数量尽可能大、尽可能新的且性能好的高效模型

**实现内容：**
- ConvNeXt-V2 选型：Femto (78M) / Atto (28M) / Pico (9M) 三档
- 桌面 GPU: Femto + Atto
- 桌面 CPU: Atto + Atto
- 移动端 INT8: Pico
- ONNX Runtime 部署：CUDA / DirectML / CoreML / CPU 多后端
- 视角级交叉注意力融合 (View-Level Cross-Attention)

---

### 6. 微距图权重

**用户需求：**
> 微距微痕图片的权重是普通图片的10倍

**实现内容：**
- `MicroWeightedSampler`：微距图样本采样频率 ×10
- 微距 tile 增强管线：不加旋转（工痕方向有意义），仅色彩抖动
- 四阶段训练策略中第 3 阶段专门训练微距流

---

### 7. 数据来源

**用户需求：**
> 数据来源：用户输入/标注的图片数据，博物馆网站爬取，科学出版社《中国出土玉器全集》《中国传世玉器全集》

**实现内容：**
- 88 个博物馆站点爬取清单（中央级 3 + 省级 34 + 市级/遗址 21 + 海外北美 15 + 欧洲 8 + 亚洲其他 5 + 其他 3 + 图书 2）
- 爬虫基类 `BaseJadeSpider`：学术身份标识 + 随机延时 3-8s + 单线程 + 固定 IP
- 反封禁策略：不并发、不高速、不换 IP、写明学术用途
- 《中国出土玉器全集》PDF 批量导入 (60 PDF, 3934 页)

### 8. 标签编码格式

**用户需求：**
> 数据标注加一些标签，对手工标注的真品给出 0、总登录号，以标注当天日期和时间开始，接着是按上诉14个年代依次以ABCDEFG排列，接着是序号；1、品名；2、材质；3、尺寸；4、来源

**实现内容：**
- 编码格式：`{真伪代码}_{总登录号}_{日期时间}_{年代代码}_{序号}`
- 示例：`0_JY20260802000001_20260802143025_G_001`
- 真伪代码：0=真老, 1=新仿
- 年代代码：A=文化期 ~ N=现代
- 总登录号：JY + YYYYMMDD + 6位流水号
- 标注字段：品名（时代+材质+器型）、材质（12大类枚举）、尺寸（长/宽/高/厚/直径, mm）、来源（馆藏/拍卖/著录）

---

### 9. 标注文件持久化

**用户需求：**
> 把标注结果保存到两个文件，真和伪并不断更新，而且提示用户给出鉴定结果的时候是否保存进入标注

**实现内容：**
- 双文件：`genuine.jsonl` (真老) + `fake.jsonl` (新仿)
- JSONL 逐行追加，flush 落盘
- AI 鉴定后四选一弹窗：保存为真老 / 保存为新仿 / 修正后保存 / 不保存

### 16. 交互式 OCR 审查

**用户需求：**

**实现内容：**

### 17. 黑底玉器图裁剪

**用户需求：**
> 审查后确认为非玉器的数据不用编辑，确认为玉器的数据把黑色背景的玉器图片crop下来重新送审查，把剩余部分的文字部分存成另一张图片也显示出来共人工核查

**实现内容：**
- `image_splitter.py`：页面自动分割
- 黑底玉器照片区域检测（RGB < 30 暗像素聚类）
- 文字描述区域裁剪
- 审查页双图显示：📷 玉器照片（黑底）+ 📝 文字描述区域
- 确认保存后，裁剪图存入 `training_data/{年代}/` 按年代分目录

### 18. 训练数据存储

**用户需求：**
> 把经过黑底裁剪的玉器图片单独存储用于后续的训练使用

**实现内容：**
- `training_data/` 目录结构：A_文化期/ ~ N_现代/
- `training_manifest.jsonl`：训练集索引
- 每次审查确认时自动复制裁剪图到对应年代目录
- 字段：piece_id, era_code, era_name, authenticity, material, product_name, training_image

### 19. 审查标签追踪

**用户需求：**
> 经过审查的数据可以在标注页面的标注预览里继续标注，标注->审查->标注迭代环节的每个步骤的结果都保存到训练数据，并在训练数据里添加一个tag，用来标记是否已经审查过已经标注审查的次数

**实现内容：**
- `review_count`：统一计数（审查 + 编辑标注 + 新建标注）
- `review_status`：imported → reviewed → annotated
- `last_reviewed_at`：最后审查时间戳
- 预览列表显示 `✅×N` 标签
- 审查页显示审查状态 + 审查日期
- SQLite 列持久化 + API 返回

### 20. 标注预览加载优化

**用户需求：**
> 标注预览加载超时的bug没有解决

**实现内容：**
- 服务端分页：`/annotations?limit=200&offset=0`
- API 返回 `total` 字段
- 初始加载 200 条 (~2s)，非全量 3934 条
- "加载更多" 按钮
- AbortController 15s 超时 + 错误提示

**相关问题修复：**
- 移除 `/annotations` 端点中的 O(n²) JSONL 扫描
- `training_image` 改为 SQLite 直接列，O(1) 读取
- 前端直接 fetch 替代 electronAPI 桥接（浏览器开发模式兼容）
